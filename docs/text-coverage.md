# 汉化资源覆盖与限制

构建使用仓库中的正式汉化文本与图片，格式处理及容量校验由随库脚本执行。

| 类型 | 输入与处理 |
| --- | --- |
| 事件与战术文本 | `work/translation/events/`；根据控制字、指针与字段布局导入，已确认指针文本可重排 |
| 主程序菜单与战斗 HUD | `work/translation/narrow/0-narrow-menu.txt`、`0-battle-ui.txt`；按已验证槽位与指令写回 |
| MM/MEM 共享名称与装备 | `work/translation/narrow/` 下对应字段模板；按实际字段边界与字节容量校验 |
| 主字库 | 用户提供的寒蝉点阵体 16px，结合原盘字库及已分配字码生成 |
| 小字库 | 默认 8×12 使用 MZPXorig，Fusion Pixel 8px 用于基础编码和战斗 HUD，并生成运行时挂钩 |
| 图片 | `work/imageedit/` 中的编辑 PNG，按原图相对路径、调色板、图块池与资源格式回写 |
| PAC/PS 与主程序 | 重建压缩资源、应用已确认补丁，并回读校验 |
| 光盘镜像 | 从日版 BIN/CUE 构建新的 BIN/CUE，更新 ISO9660 资源布局与扇区 ECC |

图片回写覆盖已确认的 WB 地名条、普通 tilemap、TITLE 嵌套资源、MM/MEM 菜单精灵、BUP 存档界面和 START.PS 按键提示。未提供编辑图的资源保持原文；导出工具不会为未知格式生成占位图。

事件控制标签、原文选择器和未经确认的原始字必须保留。定宽文本不可跨越相邻字段，图片不能任意扩展图块或像素池。构建器拒绝缺字、旧元数据、来源不匹配、容量超限等情况，不会自动猜测未确认结构。

8×12 是完整译文的默认字库构建模式，输出到独立目录；战斗 HUD 仍保留单行 8×8 路径。字体、纹理与运行时布局存在相互约束，更换字体后需要重新检查实际显示。

最终镜像回读校验验证写入结果与资源一致性，不代表全剧情、战斗、存档和硬件兼容性测试已经完成。使用流程见[构建流程](translation-build-workflow.md)。
